## Экипажи и переносы в версии 3.3.2

В окне «Мои водители и машины» перевозчик закрепляет за водителем тягач и прицеп. При выборе ФИО в заявке подставляются номера. Водитель видит закреплённую технику в своём кабинете. После переноса даты перевозчик и водитель подтверждают её отдельно. Повторный перенос отменяет прежние ответы.

## Кабинеты и обратная загрузка в версии 3.2

«Партнёры» доступны всем ролям. Введите четыре символа названия или ИНН и выберите компанию. Входящее приглашение можно принять или отклонить. Перевозчик самостоятельно вносит водителей в свой график. Руководители компаний создают персональные кабинеты в разделе «Сотрудники». На заявке сохраняется фамилия автора. У участников рейса есть общий редактор, защита от перезаписи чужих изменений и первоначальная стоимость. При отмене участники получают уведомление, запись остаётся в разделе «Отменённые» ещё 24 часа.

Перевозчик открывает конкретному партнёру график в его строке. Виден автомобиль, даты и города. Он может отозвать доступ. Для автоматического подбора по своим заказчикам укажите затраты, местоположение свободной машины и город возврата в «Параметры подбора». После рейса система использует город выгрузки. Подбор учитывает резерв, отпуск известного водителя, тип машины, доступный срок, порожнюю подачу, стоимость гружёного пути, возврат к базе и ожидание. При отсутствии введённого дорожного пробега оценка равна расстоянию между центрами городов, умноженному на 1,25. Неизвестный маршрут остаётся без финансовой оценки. Начальные затраты условны. При отсутствии точного времени стыковки показано, что его нужно уточнить. Окончательное назначение выполняет человек.

Кабинет администратора сайта расположен по адресу `/admin`. Владелец задаёт отдельные `LOGISTIK_SITE_ADMIN_LOGIN` и `LOGISTIK_SITE_ADMIN_PASSWORD` в настройках существующего сервиса. Блокировка по ИНН закроет вход соответствующим компаниям и сотрудникам. Удаление убирает компанию с площадки и сохраняет историю рейсов её партнёров.

## Диспетчерские графики 3.1

Заказчик задаёт день и время подачи. В очереди есть номер внутри дня, экипаж и число назначенных машин. Кнопка «Отправить заявку» адресует рейс конкретному партнёру. Встречное время выделено красным до решения заказчика. Решение записывается в журнале и обновляет кабинеты.

Перевозчик добавляет водителей в свой пул, открывает недельный график по фамилии и вносит сторонние рейсы. У водителя календарь на месяц с выбором дня, рейсами от нескольких перевозчиков и отпуском. Отпуск исключает назначение экипажа и конфликтующие резервы. Для новой организации требуется ИНН. В ранее созданных кабинетах руководитель может заполнить его в разделе «Учётная запись». Число участников для роли не ограничено настройкой продукта.

В открытом кабинете сигнал заявки длится три секунды. Для проверки звука используйте кнопку «Послушать двигатель» в своей учётной записи.

## Возможности

- Три кабинета, персональные пароли, серверные организации/роли, сессии и CSRF.
- Заявки, календарь, таблица, договорная/ограниченная открытая видимость.
- Предложения, согласие с условиями, резерв экипажа перевозчиком, окончательное подтверждение заказчиком даже при совпадении ставки.
- Отзыв/отклонение предложения, отмена с удалением через сутки, завершение, журнал действий.
- Ставки конкурентов скрыты. Участники назначенного рейса могут изменить общую карточку и стоимость.
- Учётная запись с именем, ролью и email видна в каждом кабинете, включая мобильный размер.
- Одноразовые резервные коды восстановления пароля для всех ролей; отзыв всех сеансов при восстановлении. Автоматической почтовой отправки нет.
- Взаимные приглашения компаний, пул водителей заказчика, подключение водителя к перевозчику; сохранённая история без повторных приглашений, архив/возврат, удаление из пула и личные комментарии.
- Сохраняемые уведомления участникам после каждого действия с заявкой, SSE и две перегазовки дизеля. Фоновый Web Push с разрешением устройства, очередью и повтором при временных ошибках. Физическая слышимость и доставка зависят от устройства и работающего сервера.
- Экспорт CSV, атомарный импорт до 300 черновиков, защита от повторной отправки.
- Резервная копия SQLite/PostgreSQL и восстановление в пустую БД.
- PostgreSQL: общая транзакционная advisory-блокировка записей, включая разные процессы и заявки, претендующие на одного водителя/машину.
- Идемпотентное добавление полей старого пилота с журналом версии схемы.

Все исходные CSS-правила утверждённого HTML сохранены. Дополнения для входа, уведомлений и исправления мобильного переполнения восстановлены из 2.6.1. В 2.8.0 и 2.9.0 CSS также не менялся.

## Проверка

Финальная приёмка 2.9: **85 тестов + 5 HTTP-сеансов + PostgreSQL + 8 проверок фонового обработчика + Chromium/Firefox/WebKit и мобильная ширина** — [успешный запуск](https://github.com/dema66362-droid/Logistics/actions/runs/44542194861). Подробности и границы проверки — в [отчёте 2.9](docs/ACCOUNT_POOL_NOTIFICATIONS_2_9.md).

Нужен Python 3.12. Проверенные версии закреплены в constraints.txt.

~~~bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt -c constraints.txt
.venv/bin/python -m pytest -q
.venv/bin/python verify_multiuser_http.py
node scripts/verify_push_worker.js
~~~

В Windows используется .venv/Scripts/python.exe. Последняя команда требует разрешения на локальные сокеты.

Для настоящего PostgreSQL задайте LOGISTIK_QA_DATABASE_URL на отдельную тестовую БД и выполните:

~~~bash
python scripts/verify_postgres.py
python -m pip install -r requirements-browser.txt -c constraints.txt
python -m playwright install --with-deps chromium firefox webkit
python scripts/verify_roles_browser.py
~~~

Сценарий создаёт свои случайные схемы и не очищает существующие таблицы приложения. GitHub Actions запускает API, HTTP и PostgreSQL QA после публикации в main. Наличие workflow само по себе не означает успешный запуск. В принятом релизе результаты привязаны к конкретному коммиту в записи приёмки.

Прежние scripts/check_server_ui.py и scripts/test_login_browser_26.py проверяют отрисовку с подменённым API. Они не подтверждают сквозную работу браузера с сервером.

## Учебный стенд

render.yaml описывает Python-сервис и PostgreSQL. Проверьте существующие ресурсы, подтверждённое пространство, регион и условия тарифа. Не создавайте вторую БД, если уже есть подходящая. GitHub хранит код; GitHub Pages не запускает Python API/PostgreSQL.

Для уже существующей `logistik-pilot-db` используется `render.existing-db.yaml`: только бесплатный веб-сервис во Франкфурте, ссылка на существующую БД и пять независимых паролей, генерируемых Render. Эта конфигурация применена в подтверждённом My Workspace; автосинхронизация и авторазвёртывание отключены. База остаётся вне управления Blueprint. Следующие изменения приложения требуют проверенного ручного развёртывания.

start_render.sh проверяет конфигурацию и создаёт пять учебных аккаунтов в пустой БД. Повторный запуск сохраняет данные и изменённые пароли.

| Кабинет | Логин | Секрет среды |
|---|---|---|
| Заказчик | pilot.shipper@example.test | LOGISTIK_TEST_SHIPPER_PASSWORD |
| Перевозчик Б | pilot.carrier1@example.test | LOGISTIK_TEST_CARRIER1_PASSWORD |
| Водитель Б | pilot.driver1@example.test | LOGISTIK_TEST_DRIVER1_PASSWORD |
| Перевозчик В | pilot.carrier2@example.test | LOGISTIK_TEST_CARRIER2_PASSWORD |
| Водитель В | pilot.driver2@example.test | LOGISTIK_TEST_DRIVER2_PASSWORD |

Пять разных случайных паролей 18–128 символов задаются в секретах хостинга, никогда в репозитории.

Для Web Push приватный ключ P-256 PKCS8 DER в base64url хранится только в секрете LOGISTIK_VAPID_PRIVATE_KEY; LOGISTIK_PUBLIC_URL содержит публичный HTTPS-адрес сайта. Не публикуйте ключ. Его замена требует повторного подключения устройств.

Обязательные настройки: LOGISTIK_DEMO=0, LOGISTIK_ALLOW_SIGNUP=1, LOGISTIK_SECURE_COOKIE=1, LOGISTIK_DEPLOYMENT=pilot, LOGISTIK_DATABASE_URL с PostgreSQL, hostname в LOGISTIK_ALLOWED_HOSTS. Календарный день по умолчанию — Москва (LOGISTIK_TIMEZONE). Режим production пока блокируется.

После Live проверьте /health: status=ok, version=3.3.2, затем пройдите [приёмку](docs/FINAL_TEST.md) с разных устройств.

## CSV и копии

[Шаблон импорта](docs/import_template.csv). POST /api/import.csv принимает JSON с полем csv и заголовком X-CSRF-Token сессии заказчика. UTF-8, разделитель ;, поля CreateShipment. Весь файл проверяется до записи. Повтор того же файла той же организацией возвращает прежние номера без дублей. Поиск не запускается автоматически. Кнопка импорта в утверждённый интерфейс не добавлялась.

~~~bash
python backup_db.py backup backups/pilot_snapshot.json
python backup_db.py restore backups/pilot_snapshot.json --confirm-empty-database
~~~

База задаётся через LOGISTIK_DATABASE_URL. Непустой приёмник отклоняется. Снимки содержат хеши паролей и бизнес-данные: храните их закрыто. Сессии и Push-подписки не восстанавливаются. Восстанавливаются история приглашений, личные комментарии и хеши резервных кодов; неиспользованные приглашения отменяются, чтобы не оживлять старые ссылки. Контрольная сумма выявляет случайное повреждение и не заменяет защищённое хранение.
