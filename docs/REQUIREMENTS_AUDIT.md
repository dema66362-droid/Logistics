# Аудит требований «Логистик»

19 ноября 2026, Москва. Рабочая версия 2.9.0.

## Достоверность источников

Прочитаны исходники 2.6.1, утверждённый logistik_ui_simple.html, архивы 1.0/2.0/2.5, logistics_mvp_spec.md, STATUS_REPORT.md, RELEASE_AUDIT.md, STATUS_DEPLOYMENT_RU.md и инструкция публикации. Получены доступные фрагменты решений из прежнего чата.

**Полный построчный текст исходного чата не предоставлен.** Это аудит доступных требований/кода, а не подтверждённый анализ каждого сообщения переписки.

Последние требования пользователя: индивидуальные входы и видимая учётная запись, восстановление пароля, приглашения всех трёх ролей, удаление из пула, личные комментарии и уведомления участникам каждого действия с заявкой. Дизайн сохраняется. Бизнес-сценарий: заявка → предложение → подтверждение водителя → назначение → завершение.

## Исправления 2.7.0

1. Обычный pytest больше не импортирует bootstrap-скрипт как тест.
2. PostgreSQL получил общую транзакционную блокировку вместо зависимости только от Python RLock.
3. Ограничение входа хранится в БД; успешный вход другого пользователя не обнуляет ошибки. Выдача сессии атомарна относительно смены пароля.
4. Проверяются пустые названия, дробность объёма, даты, конечность чисел и стоимость после пересчёта.
5. Выход/отзыв сессии очищает UI и SSE. Поздний ответ API не восстанавливает предыдущего пользователя.
6. CSV проверяется до записи; повтор не создаёт дубли.
7. Возвращено резервное копирование/восстановление. Снимки исключены из Git, сессии не восстанавливаются.
8. Добавление старых полей работает для SQLite/PostgreSQL под блокировкой, с журналом версии схемы.
9. Закреплены проверенные зависимости, добавлены CI и протокол приёмки.
